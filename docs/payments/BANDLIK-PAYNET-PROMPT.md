## Goal
Bandlik must serve the **Paynet (UZPAYNET) provider endpoint** so users can top up their Bandlik wallet at a Paynet agent (terminal / kiosk / Paynet app). Paynet and SlaydX already share ONE Paynet service (one `serviceId`, one login/password). Paynet calls **SlaydX's** URL; SlaydX authenticates the call, and when the payer id starts with **`vk-`** (or `vk_`) it relays the request to Bandlik **unchanged** (same body, same `Content-Type`, same `Authorization: Basic …` header, plus `X-Forwarded-By: slaydx`) and returns Bandlik's JSON reply to Paynet verbatim. So Bandlik only has to implement the provider side, exactly as Paynet specifies it. The relay target is `POST https://<bandlik domain>/api/payments/paynet` (FastAPI router mounted under `/api`, next to the existing Click callback). Make sure nginx/FastAPI route that path (POST, JSON, no auth cookie).

SlaydX already did this side live (reference behaviour, 11/11 on Paynet's own tester): mirror its semantics. The existing Click code (`webapp/payments/shop.py`, `merchant.py`, `config.py`, migration `m020_click_payments.py`, `tests/test_payments_click.py`) is your template for orders, the ledger (`wallet_transactions.reference` UNIQUE), the payment bonus and the raw event trail.

## Protocol (JSON-RPC 2.0, UTF-8, HTTPS)
- Request: `{"jsonrpc":"2.0","method":"…","id":<string|number>,"params":{…}}`. Response always echoes `id`. HTTP **200** with a JSON-RPC body for everything, except bad/missing credentials → **HTTP 401** + `WWW-Authenticate: Basic realm="paynet"` + `{"jsonrpc":"2.0","id":null,"error":{"code":412,"message":"Неверный логин или пароль"}}`.
- **Auth:** HTTP Basic, username/password from env `PAYNET_USERNAME` / `PAYNET_PASSWORD` (**the same values SlaydX uses; the owner writes them into the server `.env` himself — never invent, log, print or ask for them**). Compare in constant time (compare sha256 digests with `hmac.compare_digest`); if either env value is empty every call is a 401. Never log or store the `Authorization` header or the password.
- Dates: `YYYY-MM-DD HH:mm:ss` in **GMT+5 (Asia/Tashkent, no DST)**. Body cap 64 KB (reject bigger with `-32600`).
- Envelope errors: invalid JSON `-32700`; not a single object with `jsonrpc:"2.0"`, string `method`, `id`, object `params` → `-32600`; unknown method (including `ChangePassword`) `-32601`; missing required params `-32602`; any internal failure `-32603` (never leak details); non-POST `-32300`.
- `serviceId` must be an integer in env `PAYNET_SERVICE_IDS` (comma list; the owner sets it to the same id SlaydX uses), else error **305**.
- **Payer id:** `params.fields.client_id` is a string `vk-<Bandlik user id>` (accept `vk_` too; case-sensitive; strip the prefix, the rest must be digits). Absent → **411**; malformed → **401**; no such user → **302**; blocked/banned user → **501**. (Keep the field name configurable: env `PAYNET_CLIENT_PARAM`, default `client_id`.)

## Methods
| Method | Params | Success result / errors |
|---|---|---|
| `GetInformation` | `serviceId`, `fields` | `{"status":"0","timestamp":"<now>","fields":{"name":"<masked name>","balance":<wallet balance in SO'M, integer>}}`. Mask: first token + initial of the second (`Adham B.`), one token as is, empty → `Bandlik`. **balance is in so'm, not tiyin** (Paynet's tester requires it). |
| `PerformTransaction` | `amount` (**tiyin**, integer), `serviceId`, `transactionId` (Paynet's positive integer), `fields` | Validate: `amount` a positive integer **multiple of 100** else **413**; so'm value below the Click minimum → 413, above the maximum → **415**; `transactionId` a positive safe integer (digit string accepted, canonicalise: `"000123"` ≡ `123`) else `-32602`. **Idempotent:** a repeated `transactionId` → error **201** and NO second credit (also under concurrency: one credit, the rest 201). Success: `{"timestamp":"<perform time>","providerTrnId":<our integer id>,"fields":{"client_id":"<vk-… as sent>","balance":<new balance in so'm>}}`. Credits `amount/100` so'm to the wallet **in ONE transaction with the order row** (order insert + wallet credit + ledger row + payment bonus together; use `BEGIN IMMEDIATE` so SQLite serialises concurrent calls; a failure after the insert must leave no order and no credit). |
| `CheckTransaction` | `serviceId`, `transactionId`, `timestamp` | found+paid `{"transactionState":1,"providerTrnId":N,"timestamp":"<perform time>"}`; unknown id `{"transactionState":3,"providerTrnId":0,"timestamp":"<now>"}`. Invalid `timestamp` → **414**. |
| `CancelTransaction` | `serviceId`, `transactionId`, `timestamp` | **Never cancels** (owner policy: payments are final). Found → error **77**; not found → **203**. Nothing is ever changed. |
| `GetStatement` | `serviceId`, `dateFrom`, `dateTo` | `{"statements":[{"amount":<tiyin>,"transactionId":<int>,"providerTrnId":<int>,"timestamp":"<perform time>"}]}` — **only Bandlik's own PAID Paynet transactions** with perform time in `[dateFrom, dateTo]` **inclusive at second resolution** (everything up to `dateTo`+999 ms), ordered by time then transactionId, no cap below ~50 000 rows. Invalid or reversed dates → **414**. SlaydX merges this list with its own for Paynet's nightly reconciliation and **fails the whole statement if yours errors or is malformed**, so it must be correct, strict JSON, and fast. |

## Data model (SQLite, new ordered migration `mNNN_paynet.py`, additive)
- Rebuild `payment_orders` / `payment_events` the way `m020` rebuilds `wallet_transactions` so the `provider` CHECK also allows `'paynet'` (the Click CHECK is `IN ('click')`). Add to `payment_orders` a numeric `paynet_trn_id` (our `providerTrnId`; the table's own integer `seq` is fine to reuse if it is unique and never reused).
- A Paynet top-up is a normal `payment_orders` row: provider `paynet`, purpose `topup`, `provider_txn = str(transactionId)`, state `paid`, times in unix **ms**; the existing unique index `(provider, provider_txn)` is the idempotency guard. Ledger: `wallet_transactions` kind `topup`, `reference = "paynet:<transactionId>"`; the payment bonus (existing `payment_bonus_percent` setting) exactly as Click does (`payment-bonus:<order id>`). Reuse the existing settle/credit function; do not write balances by hand.
- Every authenticated call → one `payment_events` row (provider `paynet`, method, order id, transactionId, params with secrets redacted, response code). One log line per call (method, serviceId, code, ms) — never the body, header or password.
- Statement query needs an index on `perform_time` for paid Paynet orders.

## Performance + safety
- Total handler time **≤ ~300 ms** (Paynet's budget is 500 ms and SlaydX's relay adds ~20–50 ms): few short queries, no outbound calls on this path, no slow imports.
- **Do not IP-filter** by Paynet's ranges (all calls arrive from SlaydX's server; Paynet's IPs are enforced there). `X-Forwarded-By` can be forged: rely on the Basic credentials only.
- Amount limits: reuse the Click top-up min/max constants.
- Never relay or call anything to SlaydX from Bandlik.
